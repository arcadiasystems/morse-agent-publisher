The handover

Treat it like a contractor.
Hand it three things.

A rules file so it starts from the docs, a shell with its own key, and a job described by its outcome. All three come from the recipe; copy them and change the names.

# Morse
This project publishes to a Morse publication on Sui
testnet. Before using the Morse CLI or SDK, read
https://docs.morsecms.xyz/llms-full.txt (or01

Rules
- Use the CLI non-interactively:
  `morse --json -q --yes ...`02
- Never run `account export`, never print
  MORSE_PRIVATE_KEY.03
- New post:
  `morse entry add <name> --file <path> --epochs 30`
- Edit an existing post:
  `morse revision publish-direct <entryId>
  --file <path> --epochs 30`
- Look up entry ids in morse-map.json; update it04
  after every add.
- Read back with `morse entry read <entryId>`.

  • 03
    The key stays unprinted.The agent may not export its key or print it into a log.
  • 04

The commands

Two machines. Two keys.

Five steps, in order. Three run on your machine with the owner key. Two run in the agent's shell with a key that can publish to one publication and do nothing else.

YOUR MACHINEOWNER KEY
THE AGENT'S SHELLITS OWN KEY
  1. You

    Issue a cap to the agent's address. It arrives in the same transaction; there is nothing to hand over.

    $ morse cap issue 0xAGENT_WALLET_ADDRESS
  2. NO CAP YET · IT CANNOT WRITE
  3. The agent

    Check the setup. Same context you have, with no keystore and no prompts.

    $ morse --json -q --yes status
  4. YOU ARE NOT IN THE LOOP · THE OWNER KEY STAYS HOME
  5. The agent

    Publish. JSON comes back for it to read, with the entry id and the transaction digest.

    $ morse --json -q --yes entry add \
    hello-world \
    --file posts/hello-world.md \
    --epochs 30
  6. You

    Look. What exists now, and which caps that address holds, revoked ones included.

    $ morse entry list
$ morse cap list 0xAGENT_WALLET_ADDRESS
  7. You

    Revoke, without touching the agent. The CLI asks you to confirm first.

    $ morse cap revoke 0xAGENT_CAP_ID
  8. AFTER STEP 05 · ITS NEXT WRITE ABORTS ON CHAIN

Commands and flags checked against morse-cli 0.14.0 with --help on 19 Nov 2026. No transaction was sent for this page. Building the agent on the SDK? The same write is addEntryFromBytes with a KeypairAdapter made from the agent's key: see the SDK cookbooks.

Audit and revoke

The audit log is Sui itself.

Every write the agent makes is a transaction signed by its own wallet. You do not ask the agent what it did. You read the record.

  1. YOUcap issue

    The cap goes to the agent's address.

    RETURNS · CAP ID, DIGEST
  2. THE AGENTentry add

    A new post. Bytes to Walrus, the record to Sui.

    RETURNS · ENTRY ID, DIGEST
  3. THE AGENTrevision
    publish-direct

    A correction is a new revision. The earlier one stays on the record.

    RETURNS · DIGEST
  4. YOUcap revoke

    Takes effect on the next transaction.

    RETURNS · DIGEST
  5. THE AGENTentry add

    Aborts on chain. The cap is now a dead object in its wallet.

    NO RECORD WRITTEN
What it published stays.Revoking stops the next write. Nothing the agent already published disappears.
A wrong post is yours to fix.Append a revision, or delete the entry, from your own wallet.
One thing to know.entry add uploads to Walrus before it writes to Sui, so a write attempted after revocation still pays for the upload, then fails.
Scope

Two keys.
Only one leaves.

There are no user accounts in Morse. Write access is an object, so what the agent can do is short enough to read.

STAYSOwnerCap

Yours. One per publication.

  • issue and revoke caps
  • transfer ownership
  • delete
GOESPublisherCap

The agent's. Revocable.

  • create collections
  • add entries
  • append and publish revisions
  • decrypt team content

Everyone else holds nothing and can read public entries. Anyone can list the caps an address holds; there is no private team page.

FROM THE RECIPE · DO, AND DO NOT
  • Give the agent a wallet with days of budget.Give it the owner key, or months of funds.
  • Point it at llms-full.txt.Paste commands you have not tested into its prompt.
  • Keep morse-map.json in the repo.Let it guess entry ids.
  • Review the first few posts before you stop reviewing.Assume it read the docs.

A cap holder can also decrypt posts encrypted for the team. Encryption works out of the box on Testnet only; see the limits below.

What this is

A recipe.
Not a service.

Nothing here is hosted for you, and no account stands between your agent and your publication. That is the point. It also leaves four things for you to know.

  • 01
    You run it.The recipe is a docs page. The tools are the Morse CLI and SDK, both before 1.0.
  • 02
    Walrus Mainnet is real money.Public content works there, and the SDK's own word for it is usable but young. No faucet. Start on Testnet.
  • 03
    Storage is a paid lease.--epochs sets how long the content is paid for. When the lease ends the content can go offline, while the record on Sui remains.
  • 04
    Encryption is Testnet-ready only.Seal works out of the box on Testnet. On Walrus Mainnet you supply your own Seal key-server credentials.

Questions

Before you issue one.

Is Agent Publisher an app I install?

No. It is a documented way to do one job with tools that already exist: the Morse CLI and SDK. The recipe is a page in the Morse docs, with a rules file to copy. Nothing is hosted for you.

Does the agent ever hold my owner key?

No. The agent signs with its own wallet and holds one PublisherCap. Issuing and revoking caps needs the OwnerCap, which stays on your machine.

Which agents does it work with?

Any agent runtime with a shell. The rules file works as CLAUDE.md, AGENTS.md or Cursor rules. An agent built in TypeScript can call the SDK directly without shelling out.

What happens to its posts after I revoke?

They stay, with their records. Revocation takes effect on the agent's next transaction. If it published something wrong, you append a revision or delete the entry from your own wallet.

Does it run on Walrus Mainnet?

For public content, yes: pass --network mainnet or set MORSE_NETWORK. The recipe is written for Testnet, and the CLI targets Testnet unless you say otherwise. On Walrus Mainnet every write spends real SUI and WAL, and encrypted posts need your own Seal key-server credentials.

How long does a post stay readable?

As long as its storage is paid for. Walrus storage is a lease counted in epochs, set with --epochs when the agent publishes. When a lease ends the content can go offline; the record of what was published, when and by which wallet remains on Sui.
